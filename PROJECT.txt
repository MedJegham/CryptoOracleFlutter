--------------------------------------------------------------------------------
1. WHAT IS CRYPTO ORACLE?
--------------------------------------------------------------------------------

Crypto Oracle is a cryptocurrency market dashboard with short-term AI / technical
predictions. It lets the user:

  - Browse real-time crypto market data (price, 24h change, volume, market cap)
  - Open a coin detail page with a 7-day price chart
  - See short-term predictions on two horizons:
      * H+1 (1 hour)
      * H+4 (4 hours)
    with a confidence score and a bullish / bearish / neutral direction.
  - Build and persist a personal watchlist
  - Search across 100+ symbols
  - Switch between light and dark theme
  - Sign up / log in with real Firebase email-password accounts

--------------------------------------------------------------------------------
2. TECH STACK
--------------------------------------------------------------------------------

  Framework        : Flutter (Dart, SDK ^3.9.2), Material Design 3
  State management : flutter_riverpod (StateNotifier, FutureProvider, family)
  Routing          : go_router (declarative, auth-aware redirects)
  Auth backend     : firebase_core + firebase_auth (Firebase project: cryyptooracle)
  Networking       : dio + connectivity_plus
  Models           : freezed + json_serializable (code-generated)
  Local storage    : flutter_secure_storage (auth token + uid),
                     shared_preferences (theme, watchlist ids),
                     hive / hive_flutter (cached market data)
  Charts / UI      : fl_chart, shimmer, intl, equatable
  Market data      : Binance public API (https://api.binance.com/api/v3)
                     No API key required.

4. AUTHENTICATION (FIREBASE)
--------------------------------------------------------------------------------

Auth is handled by Firebase Auth (email / password). The Firebase project is
named "cryyptooracle". The Flutter app is wired through the standard
FlutterFire setup:

  - `lib/firebase_options.dart`           -> generated by `flutterfire configure`
  - `android/app/google-services.json`    -> Android Firebase config
  - `lib/main.dart`                       -> `Firebase.initializeApp(...)` runs
                                             before `runApp(...)`
  - `lib/features/auth/data/auth_repository.dart`
                                          -> uses `FirebaseAuth.instance` for
                                             register / login / logout /
                                             getCurrentUser / isAuthenticated.
                                             FirebaseAuthException codes are
                                             mapped to AuthException /
                                             ValidationException with
                                             user-friendly messages.

Where user data lives:
  - Firebase Auth (cloud)         -> the user record (uid, email, displayName,
                                     password hash, creation date). Visible in
                                     the Firebase Console under
                                     Authentication -> Users.
  - flutter_secure_storage (local) -> the current Firebase ID token and uid,
                                     for fast offline auth checks.
  - Hive / SharedPreferences       -> NO user account data; only watchlist
                                     ids, cached market data, and theme.

To use the app you must register a real account (any valid email format,
password >= 6 characters). The previous mock "demo@cryptooracle.com / demo123"
credentials no longer work.

7. HOW TO RUN THE APP
--------------------------------------------------------------------------------

All commands are run from the project root:
    C:\Users\Mohamed\first_project_flutter\lib\Cryptooracle

STEP 1 - Install dependencies

    flutter pub get

STEP 2 - Generate code (freezed / json_serializable)

    flutter pub run build_runner build --delete-conflicting-outputs

  Generates *.freezed.dart and *.g.dart files. Re-run whenever a model changes.

STEP 3 - Pick a device

    flutter devices

STEP 4 - Run the app

    flutter run                   # default device
    flutter run -d chrome         # web
    flutter run -d android        # Android device / emulator
    flutter run -d ios            # iOS simulator (macOS only)

STEP 5 - Register / Log in

  Open the Register screen, create an account with a real email format and
  a password of at least 6 characters. The new user will appear in the
  Firebase Console (Authentication -> Users) and can then log in again.

9. RECONFIGURING FIREBASE (if you fork or change project)
--------------------------------------------------------------------------------

  1. Create / pick a Firebase project at https://console.firebase.google.com
  2. In Authentication -> Sign-in method, enable Email/Password
  3. Install the CLI tools (once per machine):
        dart pub global activate flutterfire_cli
        npm install -g firebase-tools
        firebase login
  4. From the project root, run:
        flutterfire configure --project=<your-project-id>
     This regenerates `lib/firebase_options.dart` and the Android/iOS configs.

10. TROUBLESHOOTING (QUICK)
--------------------------------------------------------------------------------

  "Target of URI doesn't exist" / missing *.g.dart or *.freezed.dart
      -> flutter pub run build_runner build --delete-conflicting-outputs

  "No Firebase App '[DEFAULT]' has been created"
      -> Firebase.initializeApp(...) is not being awaited before runApp,
         or firebase_options.dart is missing. Re-run `flutterfire configure`.

  "PlatformException(channel-error ...)" on Android
      -> Stop the app, run `flutter clean`, then `flutter pub get`,
         then `flutter run` again.

  "No devices found"
      -> Start an emulator/simulator, plug in a device, or use -d chrome.

  "Version solving failed" / dependency conflicts
      -> Delete pubspec.lock, then run `flutter pub get`.

  Gradle / Android SDK errors
      -> `flutter doctor`, then `flutter doctor --android-licenses`.

  CocoaPods errors (iOS, macOS only)
      -> sudo gem install cocoapods
         cd ios && pod install

  Stale build / weird runtime errors after big changes
      -> flutter clean && flutter pub get
         then re-run build_runner if models changed.
